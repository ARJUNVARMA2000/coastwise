# Coastwise · Method A

Extract concise, source-linked findings from native-text PDF inspection reports.

**PDF native text → bounded chunks → one extraction-and-grade call per chunk → local validation → defect tables, PDF evidence and exports.**

The current showcase contains eight saved Method A reports: Alameda 2017, Berkeley 2017 and the six Southwest Brooklyn DSNY inspections from 2020 through 2025.

## Forecast page

`/forecast/` leads with an area priority score, following Capstone's guidance that individual defects are rolled up into a score for each area of the structure rather than forecast one by one. Areas are 10-bent bands for the pile-by-pile reports and the named sub-structure otherwise; each gets a 0–100 score now and at the next inspection (taken as 5 years on), plus a time to intervention. The score weights and bands are placeholders to agree with Capstone and can be changed on the page. Below it, the page keeps the per-defect severity at the next inspection and time to intervention, from a deterioration and repair-timing forecast for the Method B defect rows (Alameda 2016, Berkeley 2017), using the inspector's severity code as the grade. Rebuild its data with `uv run scripts/build_forecast.py`. Each of those reports holds one inspection, so the rates are fitted on `static/forecast/training_pairs.csv` (72 linked transitions from Southwest Brooklyn, Windmill Hill and Ocean Beach Pier, produced by the team's forecasting pipeline in the shared capstone repo) and applied unchanged; the page states this at the top. The page also shows Southwest Brooklyn (DSNY) 2015–2025, the one structure with repeat inspections, from `static/forecast/brooklyn_method_a.json`: its inspections, 2025 defects and linked tracks as saved from the earlier Method A library (model-assigned grades), with repair timing recomputed from the same rates.

## Incognito uploads

On the upload page, enable **Incognito upload** before choosing the PDF. Method A runs with the same limits, findings, source evidence and CSV/JSON/Excel/ZIP downloads. The private report is visible only to the browser session that uploaded it and never enters the saved report library, shared search or collection exports. Uploading a private copy of a saved PDF does not replace the saved version.

Incognito uses temporary server files outside the persistent report directory. **Delete now** removes access immediately and cleans up the report's upload, previews, results and caches; if processing is active, file removal waits for it to finish. Completed/failed results expire after one hour; abandoned uploads expire after one hour. A cleanup task removes expired files within 30 seconds, and expired requests are denied immediately. Closing a tab is not an immediate deletion signal. Server restarts discard private sessions and reclaim orphaned temporary files. No private report content or run metrics are retained in Coastwise's durable index; ordinary hosting request logs and provider billing/retention still apply.

Report text is still sent to the configured model provider. Incognito does not promise zero-retention inference. This option supports the current single-process filesystem Railway deployment; cloud object-storage/queue hosting rejects private uploads rather than saving them. Multiple application processes do not share private session state.

## Run locally

```sh
uv sync --frozen
COASTWISE_DATA_DIR=.local/runs uv run python -m coastwise.method_a_release --data-root .local/runs
uv run coastwise serve --host 127.0.0.1 --port 8765
```

The saved showcase opens without model calls. The DSNY 2020–2025 high-reasoning runs use DeepSeek V4.1 Flash 1017 through DeepInfra, initially 24,000 native characters per chunk, up to 1,500 adjacent-context characters per side and at most four concurrent requests globally. Seventeen accepted chunks are reused; failed ranges are completed as 6,000-character and 2,000-character recovery chunks with no elapsed-time cutoff. The same $30 ledger retains initial billed/unknown charges and recovery usage. The new-upload defaults are unchanged.

## Findings and limitations

Each report opens as one report, retaining its physical sections/components, measurements, source-stated ratings, provisional project grades or uncertainty, and exact PDF quotations. CSV, JSON, Excel and ZIP use the same saved records.

Native text cannot interpret image-only pages, photographs or unreliable table reading order. Some appendix text is garbled. Repeated mentions, measurement-kind errors and rating/repair scope errors remain; inspect the source before quantitative use. Unsupported project grades remain uncertain. Missing or ungraded findings never imply sound condition.

Long pile schedules and laboratory appendices can combine multiple member IDs or include material-test and repair observations. Record counts are not counts of unique damaged members. Publication does not certify extraction or engineering accuracy. No OCR, vision, separate grader/judge or model repair stage is added.

The verified release is packaged in `src/coastwise/method_a_assets/latest.zip`, with exact report identities, checksums and limitations in `latest.json`. Startup validates the complete bundle before replacing the active runtime dataset and rebuilding its report index. Repeated startup with the same release preserves later uploads. Credentials and Git history are outside the replacement scope.
